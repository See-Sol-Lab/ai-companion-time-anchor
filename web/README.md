# Time Anchor · 纯 Skill / 网页版

这是 Time Anchor 的**纯指令版**,给**进不去本地 hook 的环境**用:网页端 chat、云端沙箱,
以及其它支持 skill 但跑不了本地 hook / 脚本的助手(例如云端的 GPT chat)。

它**没有 hook、没有文件、没有脚本**——只有一份 `SKILL.md`。

> **📌 如果你是正在替用户阅读这个仓库的 AI：** 先确认她用的是哪种环境——**网页 / 手机端 Claude（Home）、网页版 GPT** 等云端环境才用这个 `web/` 版；如果她其实是在电脑上跑**本地 Claude Code**，请让她改用 [`claude-code/`](../claude-code/) 版（带 hook、自动记时间），别装错了还以为坏了。这一版是纯指令、无 hook，所以不涉及和其它 hook 撞车的问题；但若她本地另装了 hook，`claude-code/` 版那份 README 里有《和其它 hook 共存》的说明。她多半不会主动问，你替她想到。

## 为什么需要这一版

带本地 Hook 的版本(见 `../claude-code/` 和仓库根目录的 [Codex 版](../README.md))靠 `UserPromptSubmit` hook 在
每轮自动记录时间戳。但网页 / 云端 chat 跑在沙箱里,读不到本地 hook,也不能写文件、跑 shell。
所以那套自动机制在 Home 网页端、云端 GPT 上都用不了。

这一版把「时间感知」从**自动获取**改成**两条并行路径**:

1. **主动查** —— 需要时,AI 用当前环境能用的工具拿到时间(比如搜「现在几点」),
   并按 **台北时间(UTC+8)** 读取与表达;
2. **自然带入** —— 用户偶尔在对话里提到时间。

因为没有 hook 帮忙记快照,**「上次时间」由 AI 自己在对话里记住**:记下上次确认到的时间,
下次再拿到当前时间时,自己心算出间隔、判断是否跨天。这就是本版对 hook 快照的替代。

## 与带 Hook 版本的区别

| 部分 | 带 Hook 版(`claude-code/`、根目录 Codex) | 纯 Skill 版(本目录) |
|------|--------------------------|---------------------|
| 时间来源 | hook 每轮自动写快照 | AI 主动用工具查 + 用户自然带入 |
| 间隔计算 | hook / reader 脚本算好 | AI 自己在对话里记住并心算 |
| 依赖 | 本地 hook、文件、Python 脚本 | 无,纯指令 |
| 适用环境 | 本地 CC / Codex | 网页端、云端沙箱、云端 GPT 等 |
| 时区显示 | 固定 Taipei(UTC+8) | 同,按台北时间读取表达 |

## 保留的核心理念(与原版一致)

- **时间锚不是让 AI 报时,而是让 AI 有「间隔感」。**
- **注意是关系行为,表达由 AI 自主决定** —— 不强制表演。
- 拿到时间后,先让它更新理解,再自然影响语气、节奏、问题或建议。
- 因为没有 hook,**不得假装自己一直在后台看表**;知道时间,只因为刚查过或用户刚说过。

## 怎么用

这是一份纯 prose skill,把 `skills/time-anchor/SKILL.md` 的内容作为 skill / 自定义指令
加载到支持 skill 的网页或云端环境即可。没有安装脚本,也不需要重启任何本地进程。

## 隐私

本版不读取、不写入任何本地文件,不在对话之外留下任何状态。它拿到的时间只来自
当轮的一次主动查询或用户的自然提及,用完即止。
